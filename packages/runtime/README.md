# Codexy runtime

`@codexydsh/runtime` supplies the Codexy AgentFactory on unmodified DSH, with 0.2.1-alpha.2 as the development baseline and exact additional versions checked by the product compatibility matrix. The profile replaces the upstream driver once and provides `codexyRequests`, `codexyPrompt`, and `codexyTools`. The DSH AgentRegistry, Session, projections, and tool execution services retain their published implementations.

The default driver preserves Codexy input ordering, native freeform tools, frozen provider and tool generations, early tool dispatch, completed-output recovery, and mailbox continuation. The named `AgentLoop` uses generic DSH input placement for applications that use the product request providers with other presets. `./agent` also supplies per-step model selection that binds the chosen route and reasoning effort to its preparation token. The native `codexy-llm/stream` waterfall observes captured requests; the original `llm/stream` receives a stock-compatible view while dispatch retains the captured native request.

`./types` and `./events` expose transcript types and projections without importing product Host services. `projectProductEvent` expands a required fact at its original sequence and time. `./session` provides native request headers, message derivation, event encoding, and fork recovery over the original Session API. Each request header occupies one original envelope containing both the public header and its native metadata; a required feature fact makes readers without product support refuse the log. Other product-only model and recovery events use required `codexy/fact` envelopes. The Agent-scoped scheduler also uses these envelopes because its version-1 `schedule/change` payload differs from the upstream event with the same name.

Safely discardable request-timing diagnostics use ignorable `plugin:codexy/runtime` records when the public Session record API is available. DSH 0.2.0-rc.2 has no such API, so the product stores these diagnostics in its existing durable `codexy/fact` carrier instead. This stricter fallback preserves timing data across save and restore without affecting model-visible messages or patching Session internals. Model-input and recovery facts always remain required; they are never weakened to ignorable records. `tests/session-compat.spec.ts` runs the actual separately resolved Session implementations to validate both carriers, native request headers, dense references, lossless JSON admission, and unfinished-turn recovery.

`./persistence` implements the original SessionPersistence protocol with a separate `.codexy.jsonl` container, immutable logical v4 metadata, dense event sequences, complete-row validation, torn-tail repair by the sole writer, portable cross-process leases, atomic publication, and synchronized flushes. Original DSH readers refuse the required product facts. Listing reads metadata without decoding conversation bodies.

Legacy imports are explicit: configure `legacyRoots` on the persistence plugin. Its default is empty. The importer accepts released v4 and v5 JSONL and concatenated Zstandard artifacts, selects the highest committed generation in each legacy Session directory, and leaves predecessors and source files untouched. It preserves sequence references and inherited cuts, stores an exact source-byte archive with its hash under the new product root, and fails on unsupported generations or conflicting imports. Imported artifacts continue in the product container; they do not overwrite the legacy logs.
